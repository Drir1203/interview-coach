# i面试 / AI 面师 — 商业化基建 Roadmap

> 状态：初版 · 2026-08-27
> 定位判断：差异化（真实面试记录→AI 复盘闭环 + 长期成长画像）站得住，国内无直接对标；
> 但「生产级商业化」卡在支付资质 / 成本计量 / 可观测性三块地基。本文档沉淀优先级与验收标准。

## 二、不足分层（按商业致命程度）

### P0 — 商业化可持续（先做）

| # | 项 | 现状 | 为什么 P0 | 验收标准 |
|---|---|---|---|---|
| P0-1 | **AI 成本计量 + 限流** | 无限流；额度按场次计、不按 token；免费/Pro 同模型链 | 免费层可无限调 AI → 规模即亏损；竞品普遍按量规避 | AI 接口按用户 token 计量 + 速率限制；免费/Pro 模型分层；超限返回明确错误 |
| P0-2 | **官方支付接入** | 收款码+人工确认（冷启动策略） | 无商户号→无发票/对账/退款/自动续费 | 微信支付扫码/JSAPI 接入，下单→支付→回调自动开通；退款与对账可查 |
| P0-3 | **错误追踪 + DB 备份** | 无 Sentry；deploy 不备份 DB | 一次静默挂机=直接损失；业务资产不可再生 | 生产 500 告警可达；PG 每日自动备份可恢复 |

### P1 — 生产可靠性与可观测性

- 结构化日志 + 错误追踪（现 24 处 console 散落）
- 性能/成本看板（AI 调用量、模型降级率、每用户成本）
- 任务队列（转写/复盘异步化，失败重试幂等；音频持久化策略）
- 事务通知（新订单→管理员；开通结果→用户；替代 3s 轮询）

### P2 — 增长与风控

- 转化漏斗埋点（注册→下单→付费）
- 注册风控（邮箱验证/验证码/设备指纹）
- 订阅结构补齐（年付折扣、按量档、高级模型档）
- 内容/社区承接（公众号、小红书、校招季活动）

## 三、结构性瓶颈（长期制约）

1. **支付资质 = 硬天花板**：微信/支付宝商户号需营业执照；小程序受虚拟支付规范约束。代码解决不了，是运营主体问题。
2. **免费获客 vs AI 成本矛盾**：免费层开放的正是 AI 成本最高的能力。不解决计量，增长越快亏损越快。
3. **模型上限 vs 高要求岗位**：DeepSeek 主链够通用复盘；技术面/咨询 case 需垂直数据微调（牛客 PCC≥0.85 的路径）。差异化数据（真实面试记录）是微调原料，但量小、靠留存增长——鸡生蛋。
4. **移动端维护分裂**：Web + 小程序两套代码、功能不同步，每功能翻倍成本。
5. **获客无护城河**：功能可被抄，真正护城河是「真实面试数据+长期画像」，需时间积累 + 先解决留存。

## 四、执行顺序建议

1. **P0-1 成本计量+限流**（纯代码、无需资质、最快见效）→ 本项目下一迭代
2. **P0-3 错误追踪 + DB 备份**（低成本、防灾难）→ 与 P0-2 并行
3. **P0-2 官方支付**（需先解决企业资质）→ 资质到位后启动
4. P1 按「先可观测、后队列」推进
5. P2 在 P0 完成后做增长实验
