# 录音转写 → 问答抽取：方案演进与回滚指引

> 记录长录音（上传/录音后切成 60s 分段）如何变成「逐条问答记录」的三代方案。
> 目的：线上验证一段后发现不合适时，能按本文件快速回滚到某一代，不必重新推演。

## 背景

- 长录音先由 FFmpeg 切成 60s 片段（`AudioRecorder`），再逐段 ASR 转写。
- 页面形态 = **问题列表**：一条 = 面试官一个问题 + 一段回答，可编辑。
- 三代方案差异集中在「如何从转写文本得到逐条问答」，以及「上下文是否跨 60s 切点」。

## 三代方案对比

| 维度 | A. 逐段版（旧，2f328ea） | B. 整稿浓缩版（曾上线 add0288） | C. 整稿穷举版（当前，推荐） |
|---|---|---|---|
| 流程 | 每 60s 段各自 ASR + 各自抽问答，逐段追加 | 每段只 ASR → 客户端拼完整稿 → 整稿抽一次 | 同 B：拼完整稿，但抽取语义改穷举逐条 |
| 一条记录 = | 一个问答 | 模型把多轮**合并成的一条长内容** | 一个问答（不合并多轮） |
| 50 分钟效果 | 55 段 → 15 条，首条空白 | 只 6 条、每条很长 | 逐条问答，覆盖完整稿 |
| 漏内容 | 漏：跨 60s 切点的问答后半段在下一段、无新问题 → 整段丢弃 | 漏（藏起来）：被精简/合并进长条 | 最稳：完整上下文里把被切开的回答接回 |
| 首条空白 | 有（开场白被抽成空问题） | 无 | 无（空问题直接丢弃） |
| 上下文 | 每段孤立 | 全稿上下文 | 全稿上下文 |
| 速度 | 每段一次小 LLM，逐段推进 | 尾巴整稿 LLM 串行、无进度、慢 | 窗口并行 + 调大，尾部等待显著下降 |
| 当前状态 | git `2f328ea` | commit `add0288`（已推送上线过） | 本仓库当前 main 头部（见本文件「决策记录」） |

## 路线 C 的关键实现点

文件：`src/lib/qa-extract.ts`

- 提示词 = **穷举式逐条**：每个问题独立一条、按顺序、不总结不浓缩、回答保留原话；
  同一次提问被分几段答完仍只算一条；纯寒暄/无提问跳过；问题不能为空。
- `cleanQAs` 去重 = **近邻合并**（`DEDUP_NEAR_POS = 5`）：
  - 窗口重叠/跨段把同一问答输出多次且相邻 → 归并成一条；一份含另一份、或长度差 ≥2 倍 → 取更完整那份，不拼接；长度接近且互不包含 → 视为被切开的片段按顺序拼接回完整回答。
  - 相隔很远又问到同一个问题 → **保留两条**（面试里真又问了一次）。
- 窗口 8000 字 / 重叠 1200；窗口间 `Promise.all` 并行、按序汇总；`max_tokens` 默认 6000 防截断丢尾。

## 线上验证与回滚

> 每次切换后请以「上传一段 >60s 录音 → 新建面试 → 问题列表」为验收入口：
> 期望逐条、不漏内容、首条不空白、每段耗时可接受。

| 想去哪一代 | 命令 |
|---|---|
| C（当前，推荐保留） | 无操作，即当前代码 |
| 只回滚 C 的代码改动（回到已上线的 B 形态） | `git checkout add0288 -- src/lib/qa-extract.ts tests/unit/qa-extract.test.ts`（C 只改了这两处，不含本文档） |
| A（逐段旧版） | `git revert add0288`（撤销整稿方案全部提交，回到 2f328ea 的逐段行为） |

- 上面全部是本地操作；回滚后如需上线，走常规 commit + push → GitHub Actions 自动部署。
- 注意：B（add0288）为「整稿浓缩」，曾因「只出少数长条、不像逐条记录」被否；若线上再遇到类似评价，
  优先考虑回 C（当前），而不是回 B。
